Font family: Ioskeley Mono — a monospace typeface self-hosted at /assets/fonts/ioskeleymono/ in eight static .woff2 files (weights 300, 400, 600, 700, each with an italic). No variable font is available. The regular, semibold and bold faces are preloaded from every page's <head>; the fallback stack is ui-monospace, SF Mono, Menlo, Consolas, then generic monospace.

Root font size is 18px, set on html, so 1rem = 18px and every rem value below scales from it. Body line-height is 1.5; the measure is capped at 90ch on body.

Text weights in use: light 300, regular 400, semibold 600, bold 700.

Italic variants: light italic, regular italic, semibold italic, bold italic.

icons

Icons are plain Unicode characters typed as HTML entities and rendered by the self-hosted Ioskeley Mono webfont. There is no icon font, no SVG sprite, and no CDN — they cost zero extra network requests and leak nothing to a third party. Every glyph below was verified to exist in the font at the 400, 600, and 700 weights, so they render identically on every machine.

Use the numeric entity (e.g. &#9635;) rather than pasting the raw character — it survives copy/paste and encoding changes, and makes the codepoint obvious when reading the source.

picking a new one

Before adding a glyph, check the font actually contains it. Anything missing falls back to a system font, which breaks the monospace rhythm and can render as a color emoji on some platforms. &#9998; (U+270E, the pencil ✎) is one such miss — it is not in Ioskeley Mono, which is why it is not used anywhere on the site.

Safest of all is plain ASCII, which is guaranteed present and suits the terminal tone of the site: + * > ~ # | /, or bracketed forms like [+] and [*].

capitalization

Uppercase text on this site is produced two different ways, and which one you reach for depends on whether the text is content or chrome.

typed in caps in the markup

Wayfinding text is written uppercase directly in the HTML. These read as proper names of destinations rather than styled labels:

  • .site-name — DANIEL DAUM
  • main nav — HOME, ABOUT, NOW, BLOG, PROJECTS, GARDEN
  • footer nav — EMAIL, GIT, PGP, CHANGELOG, PRIVACY
  • .nav-back breadcrumbs — GARDEN -> STYLES
  • page h1 — /BLOG, STYLES, /MICRO
  • .post-tag — #TAG1

uppercased by css

Structural labels are written lowercase in the source and uppercased with text-transform: uppercase. The source stays readable and greppable:

  • .section-label, .section-more
  • .group-label, .demo-label
  • .project-stat-label
  • .new-tag
  • .content-table thead th
  • .styles-section > h2, .styles-toc a

which to use

Prefer the CSS route for anything new. Beyond keeping the markup lowercase and searchable, it means the underlying text stays in normal case for assistive tech — some screen readers spell out all-caps words letter by letter, so PGP typed literally can be read as "P G P" while a CSS-uppercased pgp is read as a word. The existing typed-caps nav is grandfathered in; it is short and mostly initialisms already, so it is not worth churning.

stretched links

Two components make a whole card or row clickable without nesting anchors: the real link inside gets an ::after with position:absolute; inset:0, and the container gets position:relative. Used by .micro-post (via .micro-time) and .activity-item (via .activity-link).

This keeps the accessible name short — a screen reader announces just the date or the title, not the entire post body. The tradeoff is that the transparent overlay sits above the text, so text inside those components is not selectable.

media & photos

photo wall

.photo-wall / .photo-tile

A CSS grid (not columns) so photos flow left-to-right then top-down — the newest photo in the markup is always top-left. Tiles are uniform 4:5 crops via object-fit: cover; the lightbox shows the full frame. Drops to two columns below 900px and one below 480px.

.photo-caption is hidden until hover or focus-within, then fades up over a gradient scrim. .photo-tile--new marks a fresh photo with an accent outline (an outline, not a border, so the image does not shift).

.photo-wall / .photo-tile / .photo-caption — placeholders, hover a tile

.new-tag

A small accent badge reading New!, used in both the hover caption and the lightbox meta. Uppercased by CSS.

tracker walls

.tracker-wall / .tracker-tile

Books, movies, shows, games and music share one wall: an auto-fill grid of covers with the title, date and rating always visible beneath. .tracker-cover is a fixed 2:3 box (--square for album art, --boxart for 3:4 games) that shows "NO COVER" until an <img> is dropped in. .tracker-tile--new frames a fresh entry in the accent. Clicking a cover opens a .tracker-note-card inside the same .lightbox shell the photo wall uses. body.tracker-page widens the page the same way .photos-page does.

.tracker-wall / .tracker-tile / .tracker-cover / .tracker-caption

.lightbox

A fixed overlay toggled entirely by :target — no JavaScript. Each photo links to #view-n; the matching .lightbox switches from display: none to display: block. Navigation between photos is just more anchors, and the backdrop and close button both link to #.

selection & focus

Text selection uses ::selection: try highlighting this sentence — the selection background becomes var(--accent) with the page background as the text color.

Focus ring: keyboard-navigable elements receive a 2px solid var(--accent) outline at 2px offset. Mouse clicks suppress the outline via :focus:not(:focus-visible).

responsive & accessibility

breakpoints

  • ≤ 480px — mobile: reduced padding and type scale, full-width pre blocks, single-column photo wall, two-column tracker walls, pager shows arrows only, micro and reply meta rows stack, footer also drops CHANGELOG
  • ≤ 600px — header stacks the name over a 3 × 2 nav grid; .meta-split stacks; content tables stack title above date/tag; project stats stack; the about-page .figure-row keeps only its middle photo; footer drops the // marker and PGP; lightbox controls shrink
  • ≤ 768px — tablet: slightly reduced padding and heading sizes; .project-card stacks image under text; text-wrap: pretty is off
  • ≤ 900px — photo wall drops to two columns

.skip-link

First focusable element on every page. Parked above the viewport until it takes keyboard focus, then drops in at the top-left and jumps to #main. Press Tab on any page to see it.

media query features

  • prefers-reduced-motion — all transitions/animations set to 0.01ms
  • prefers-contrast: high — higher contrast palette, underlined links, thicker code borders
  • print — white background, black text, hidden nav, absolute URLs appended to links
